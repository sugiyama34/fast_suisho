# アブレーション (FT の `w_specific` を未学習に戻す)

## ツール (`ablate/`, 2026-09-29)

Python + numpy (`data/matchenv/bin/python` で実行)。

- `ablate.py --ckpt <checkpoint> --mode {none|zero-specific|random-specific} --features <list> --out <dir>/nn.bin [--verify]`
  - `state.bin` (畳み込み前の重み) を読み、対象特徴量の `w_specific` 行を書き換え、
    `w_specific + w_factor` に畳み込み、BulletOu と同じ量子化 (×127, 0.5 は 0 から遠い側へ丸め, i16 クリップ) と
    LEB128 符号化で nn.bin を書く。ヘッダと layer stack ×9 は元の nn.bin からそのままコピー
  - `zero-specific`: `w_specific` = 0 (`w_factor` は残す) = 厳密に「未学習」
  - `random-specific`: 各要素を N(0, σ²) で置き換える (PCG64, `--seed`)。σ = 学習後の `w_specific` の
    RMS。基準にする行は「構造的に現れ得て、かつアブレーション対象でない特徴量」(現れ得ない行はほぼ 0 のままで
    σ を小さく引っ張るため除く)。既定は全 1024 列で共通の σ (`--sigma-scope per-column` で列ごと)
  - 1 回の書き出し 8〜9 秒 (`--verify` 付きで約 20 秒)、RAM 約 7 GB、ほぼ 1 スレッド
- `select_features.py (--arm p10 | --ckpt <dir> | --counts ...) --percent X --by {features|occurrences} --out rare.npy`
  - 候補は構造的に現れ得る特徴量 123,053 個だけ
  - `--by features`: 出現回数の少ない順に X% の個数を取る。`--by occurrences`: 発火回数の合計が全体の X% に
    収まる範囲で少ない順に取る (x 軸の 2 種類に対応)
  - 同数のタイはシード付きの乱数順で切る (index 順だと玉位置の小さいマスに偏るため)。境界の出現回数や
    タイの分割は sidecar JSON に記録する。`--report-counts` で対局側の発火に占める割合も出せる

## 検証 (2026-09-29)

1. `none` モードで既存 checkpoint の nn.bin を**バイト単位で再現** (smoke / bench の 4 checkpoint。
   `state.bin` と `weights.bin` の両方)。小さいネットでは 2 バイト符号・クリップ・0.5 の丸めが出ないため、
   それらは合成データの単体テスト (`test_nnbin.py`, i16 全 65,536 値など) で確認した
2. `zero-specific` (p10 の教師出現回数で下位 5% = 6,153 特徴量): 変わったのは対象の 6,153 行だけで、
   値は `round(w_factor × 127)` に一致
3. やねうら王で読み込んで `readyok`、`go nodes 10000` が動く。下位 5% のアブレーションでは初期局面の
   指し手・評価値は変わらない (序盤に稀な特徴量は現れない)。全特徴量をアブレーションすると指し手が変わるので、
   書き換えた重みが実際に使われていることも確認した

## 観察: アブレーションは局の大半を変える (2026-10-01)

- 暫定の最初の 1 本 (full-e12 @ FV_SCALE 40、教師順位の下位 5% = 6,153 特徴量を zero-specific、水匠 11 と 400 ペア):
  Elo **−136.5 ± 25.0** (親 full-e12 は同じ 400 ペアで −140.0 ± 25.2)。差は誤差内
- ただし **800 局のうち親と同一の棋譜は 46 局だけ**。ペア得点が変わったのは 400 ペア中 115 ペア (29%)
- 理由: これらの特徴量は探索の発火の 4 × 10⁻⁵ にすぎないが、1 局の評価は約 2,500 万回あり、そのどこかで評価値が
  わずかに変われば探索木が変わり、以後の指し手が分岐する (探索のカオス性)。「アブレーションが効く局面が稀なら棋譜は
  ほぼ同じ」という事前の想定は外れた
- 対応のある比較の効果は残る (71% のペアは得点が変わらない) が、想定より小さい。1,000 ペアでの親との差の 95% CI は
  おおよそ ±10 Elo 程度と見込む

## 結果: 最終アブレーション (full-e16 @ FV_SCALE 48, 2026-10-01)

- 対象: full の最良 (e16 @ FV_SCALE 48, 水匠 11 と 2,000 ペアで −119.4 ± 11.3 Elo)。4 設定
  (順位 = 教師データの出現回数 / 対局 (探索) の発火回数 × 置き換え = zero-specific / random-specific) × 下位
  5, 10, 20, 30, 50, 75% の 24 ネット。`w_factor` は常に残す
- 対局: 水匠 11 (FV_SCALE 32) と 667 ペア、300k ノード。開始局面は full の 2,000 ペアの部分集合で、
  **同じ 667 局面での full-e16 = −120.8 Elo** を基準に差を取る (表と図は [results.md](results.md))
- loss: 教師の一様標本 A (95 万局面) での、アブレーション − full-e16 の対応のある差 (full-e16 の loss は 0.03285)

**Elo の差 (アブレーション − full-e16)**。各値の 95% CI は ±15〜±30 (results.md)。発火の割合は
[feature-counts.md](feature-counts.md) の表 (探索の発火に占める割合; 教師順位 / 対局順位)

分かったこと:

1. **30% までは Elo の変化が検出できない** (4 設定とも ±15 以内で、CI は 0 を含む)。下位 30% の特徴量は
   探索の発火の 0.2〜0.3% しか占めない
2. **50% で小さな低下** (−8 〜 −22、平均 −16)。1 本ずつでは CI が 0 を含むが、4 設定とも負
   (4 本は同じ親・同じ開始局面で、選ばれる特徴量も大きく重なるので独立な 4 回ではない)
3. **75% ではっきり低下** (−92 〜 −111、平均 −101)。下位 75% の特徴量は探索の発火の 4〜5% を占める
4. **zero と random の差はない**。学習した `w_specific` を 0 に戻しても同じ大きさの乱数にしても同程度に効く
5. **教師順位と対局順位の差も Elo では見えない**。教師で稀な特徴量は対局でも稀なので (TV 0.20)、選ばれる集合が
   近い。loss (教師データで測る) では対局順位の方が増加が大きい (教師で稀でない特徴量も含むため、当然の向き)
6. loss は X とともに単調に増え、75% で +0.009〜+0.013 (full-e16 の loss の 26〜39%)。Elo が動かない 30% でも
   loss の増加は検出できる (+0.0004〜+0.0007、SE の 20〜40 倍)
7. 棋譜の変化は 5% でも 667 ペア中 約 170 ペア、20% 以上ではどれも約 400 ペアで頭打ち (探索のカオス性。前節)

データ削減 (arm) との比較「アブレーション X% ≈ データ削減 Y%」は arm の対局が揃ってから
(2026-10-03 頃) [results.md](results.md) の表が自動で埋まる。

## loss の測り方 (2026-09-29)

- 固定した奏乗の標本 (全 arm 共通) で loss を測る。ラベルは奏乗の評価値そのもの
- 標本は 2 種類: **全 arm が学習に使うファイル (S1 = 001/011/021) から取る = 全 arm にとって train loss**、
  **小さい arm が使わないファイル (S0 = 010/020/030) から取る = p10〜p50 にとって held-out**。
  前者は周回数の多い arm ほど楽観的になる (過学習) ので、後者と並べて読む
- 重み付き loss (対局側の分布に寄せる) は**使わない** (ユーザー, 09-29: loss は確認用なので単純な方がよい)
- 仮説の主検定: 局面を「含む特徴量のうち最も稀なものの教師での出現回数」で層別し、層ごとの loss を arm 間で比べる
- floodgate.hcpe の test loss (学習中に記録) は副指標

## 知見として扱うもの

- (09-29, smoke 20 局面時点の暫定) **教師で稀な特徴量は、対局の探索中にもほぼ発火しない**。
  教師の出現 1,000 回未満の特徴量は探索で 0 回、1 万回未満でも探索の発火の 7.8 × 10⁻⁶。
  したがって「教師の出現回数で下位 X%」のアブレーションは対局の発火をほとんど含まず、Elo 差 ≈ 0 が予想される。
  ユーザー判断: **これ自体が新しい知見**なので、このアブレーションも残し、「≈ 0」を信頼区間付きで示す
  (差が無いことの主張なので、区間の幅 = 対局数で結論の強さが決まる)。2,000 開始局面の集計で確定させる

## 限界として論文に書くこと

- Ranger (Adam 系) は特徴量ごとに更新幅を正規化するので、稀な特徴量の不利を一部打ち消す。
  SGD で学習したモデルでは、稀さの影響は本実験より大きく出る可能性がある
- 同一レシピ (同一ステップ数) でデータを減らしても、稀な列の更新回数はほぼ変わらない
  (同じ局面を多く周回するだけ)。データ削減 arm が測るのは「更新回数」ではなく
  「異なる局面の多様性」である

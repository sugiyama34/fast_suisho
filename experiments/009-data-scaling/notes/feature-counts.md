# 特徴量 (one-hot) の出現回数の統計

## 集計ツール (`feature_count/`)

- Rust 製。BulletOu の `ShogiHalfKa2.map_features` (学習時のバッチ作成と同じ関数) を
  path 依存で呼ぶので、index は学習で使われるものと完全に一致する
- 出力はファイルごと: `<stem>.{stm,nstm,both,dropped_both}.npy` (u64[131949]) と `<stem>.json`。
  arm の集計値は、その arm のファイルの配列の和で作れる
- `both` = 両視点の合計 (loss 重み > 0 のレコードだけ)。`dropped_both` = |score| ≥ 32000
  (loss 重み 0) のレコード分。`both + dropped_both` が生の合計
- 出力先: `/mnt/nvme1/sugiyama/feature_counts/`。バイナリ sha256 `a84abcf6c69f15cd7a02107e710c3ec2cddef6fb19c17f597650b80613bf3d6a`
- 速度: 16 スレッドで 1 ファイル (4.89 億局面) 38 秒 (12.9M 局面/秒, デコード律速)

### 検証 (2026-09-29)

- cshogi 0.7.8 で独立にデコードして HalfKA2 index を式から計算し直し、ファイル 001 の先頭 2,000 局面と
  全域から等間隔の 20,000 局面で比較: **SFEN の不一致 0、特徴量の不一致 0**
- ファイル 001 の全 4.89 億局面で: 1 視点あたり特徴量は常に 40 個、自玉特徴量
  (`kb*1629+1548+kb`) はちょうど 1 個、違反 0

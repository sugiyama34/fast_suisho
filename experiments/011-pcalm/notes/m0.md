状態 (lift): `h1` = pairwise 後 (1,024)、`h2` = L1 出力 (8, shortcut を含む)、`h3` = L2 出力 (64)。
残差は `r1 = h1 − pair(crelu(FT(x)))`、`r2 = h2 − L1(h1)`、`r3 = h3 − crelu(L2(u(h2)))`、出力は `L3(h3) + h2[7]`。
FT の前活性は推論中に変わらないので、疎な FT は順伝播の 1 回だけ。推論の 1 回は幅 1,024 の要素ごとの演算と小さな密層だけ。

## 検証

1. **CUDA と Python の一致** (合成重み, 4,096 局面): BP は全テンソルで相対誤差 1.1e-6 以下。
   PC-ALM は `T ≤ 4` で 1.2e-4 以下、`T = 64` で 2.3e-4、`T = 300` で 1.0e-3、`T = 1000` で 4.3e-3
   (反復で float の丸めが増える分。発散する設定ではもっと大きい)
2. **KKT 点での一致**: 状態を順伝播の値、双対変数を BP の随伴の符号反転 (`λ_i = −δ_i`) に置くと、状態の勾配は厳密に 0、
   重みの勾配は BP と一致する (4 層とも cosine 1.000000, ノルム比 1.000000)。エネルギーの式 (論文の式 (5) を本ネットに当てたもの) が正しいことの確認
3. **`--credit bp` が改造前と同じ**: smoke (sb=2) の test accuracy 0.63913 (改造版) / 0.63963 (改造前)。
   差は GPU の非決定性の範囲 (experiment-009 の同一設定 smoke 2 回で 0.63962 / 0.63986)。BP の経路のコードは同じ関数を呼ぶ

## 推論の刻み η_h と安定性

- 参照実装は `η_h = 1 / λ_max` (推論の作用素 = エネルギーの状態に関する Hessian の最大固有値)。本実装ではサンプルごとに
  べき乗法で λ_max を求め、**全サンプルで安定になるよう最大値**を使う (刻みはサンプルによらず 1 つ)
- 初期値 (`011-init`: BulletOu の初期値から 1 step) では λ_max = 3.42 (ρ = 1, 全サンプルでほぼ同じ)、6.84 (ρ = 2)。
  η_h = 0.292 (ρ = 1), 0.146 (ρ = 2)
- η_h を 2 倍にすると `α > 0` で `T ≥ 8〜16` から発散する (論文の安定条件 `η σ² (2ρ + α) < 4` と整合)
- 合成重み (重みを大きめにしたもの) では λ_max が 7〜50 とサンプルごとに大きくばらつき、η_h = 1/50 では `T = 1000` でも
  BP に収束しきらない (遅い減衰振動)。学習が進んで重みが大きくなると同じことが起こり得るので、学習済みの重みでも測る

読み取り:

- **λ_max が初期値の 3.42 から 58 に増える**。ほぼ h1 のブロック `ρ (1 + σ_max(W1eff)²)` で決まる

## 数値誤差: 状態を順伝播からの差で持つ

- 最初の実装は状態 h を絶対値で持っていた。学習済みの重みでは PC-ALM の信号が小さく、残差 `h − 予測` が O(1) の数どうしの
  引き算になる (float32 の桁落ち)。CUDA と float64 の参照の差は L1 の勾配で 4〜7% あった
- 状態を順伝播からの差 `d_i = h_i − 順伝播の値` で持ち、予測も「順伝播の値 + 変化分」で計算するように直した。
  float64 の参照との差は全テンソルで 2e-5 以下になった (e1 / 初期値, T = 1〜32, α = 0〜1.5, ρ = 1〜2)

## 刻み η の自動設定 (`--pcalm-eta-auto`)

- 重みが学習で大きくなるので、固定の η は初期値では小さすぎ (e1 の値なら 1/20)、後半では不安定になり得る。
  参照実装の規則 `η = 1/λ_max` をミニバッチごとに追従させる: `η = 倍率 / (1.05 max(λ1, λ2, λ3))`、
  λ1 = ρ (1 + max σ_max(W1eff)²)、λ2 = 局面ごとの ρ (1 + σ_max(J3)²) のバッチ最大 (J3 は順伝播の点での h2 → p3 の Jacobian)、
  λ3 = ρ + 0.35 max |W3eff|²
- 全体の λ_max (べき乗法) と比べて: 初期値では推定 2.60 / 真の値 3.42 (結合の分だけ小さい)、e1 では 57.1 / 58.1
- 初期値・α = 1.5・ρ = 1 では η が少し大きすぎて T = 64〜256 で BP に収束しない (振動)。ρ = 2 または α = 1 なら収束する。
  α = 1.5 の arm は倍率 0.75 (`etaA0.75`) にする

## Ranger の epsilon の較正 (**旧方式。PC-ALM 自身の学習で成り立たなかったので「勾配の大きさの正規化」に置き換えた**, 下の節)

- PC-ALM の FT の勾配は BP の 1/100〜1/1000 (上の表)。BP のレシピの Ranger の epsilon は 1e-7 で、BP の FT の勾配の
  中央値 (|g| 約 1.5e-7) と同程度。PC-ALM で 1e-7 のままだと、FT の更新が epsilon にほぼ潰される (勾配の大きさの問題で、
  信用割当の良し悪しとは関係のない理由で PC-ALM が負ける)
- 較正の規則: **epsilon = 1e-7 × (FT の勾配の非ゼロ要素の |g| の中央値の比 PC-ALM / BP)**、BP の e1 の重み・8,192 局面で測る。
  探索 (調整) はしない。FT はパラメータの 99.9% なので FT に合わせる (L3 の比は 1 に近く、層ごとに合わせることはできない)
- 値は `arms.py` の `EPS_PCALM` (例: T = 2 で 1.4e-10, T = 4 で 6.7e-10, T = 8 で 2.5e-9, T = 16 で 9.6e-9)。
  epsilon が T とともに変わるので、「最良の T」は epsilon の違いも含む (交絡)
- PC-ALM 自身の e1 でこの比を測り直し、3 倍以上ずれていたら報告する (較正し直しはしない)

| Ranger の velocity: 学習に出た FT の行で √v ≤ epsilon の割合 | 12% (epsilon 1.4e-10) / 37% (1e-7) | **100%** (√v の中央値 3.8e-14 ≪ epsilon 1.4e-10) |
| 初期値からの FT の重みの移動 (‖ΔW0‖) | 497 | 166 |
| floodgate の test loss / accuracy | 0.0800 / 68.9% | 0.0814 / 67.0% |

- PC-ALM では学習中に L1 の重み (W1) が大きくなり、λ_max → 自動 η → PC-ALM の信号の大きさ、の順にすべてが小さくなる。
  FT の勾配は epsilon の数千分の 1 になり、**FT の更新がほぼ止まっていた** (Adam の更新 m / (√v + ε) が ε に支配される)。
  これは信用割当の良し悪しではなく、勾配の絶対的な大きさと optimizer の epsilon の組み合わせによる人工的な結果
- 固定の epsilon (定数) では、重みとともに動く勾配の大きさに追従できない。そこで **ミニバッチごとに PC-ALM の勾配全体を定数倍し、
  FT の非ゼロ要素の mean |g| を BP の典型値 4.0e-7 に揃える** (`--pcalm-grad-norm 4e-7`, arm 名の `gn`)。
  Ranger の設定 (epsilon 1e-7 を含む) は BP のレシピと同じになり、epsilon は BP と同じ割合 (mean |g| の約 1/4) で効く
- BP の mean |g| (batch 65,536, FT の非ゼロ要素): 初期値 2.1e-9、e1 4.3e-7、009 の full-e16 3.8e-7。e1 以降はほぼ一定なので 4.0e-7 を基準にした。
  学習の最初 (BP では epsilon が支配的な時期) だけは BP と同じにはならない
- 検証: CUDA の正規化の倍率と勾配を Python で再計算した値と一致 (相対誤差 1.6e-6 以下)。PC-ALM T=2 の e1 では倍率 8.8e4、BP の e1 では 558
- 固定 epsilon の 2 run の扱い: `s-pcalm-T2` は「旧方式」の参考として調整対局まで行う (候補にはしない)。`s-pcalm-T4` は sb 6 で止めた
  (`011-s-pcalm-T4.stopped-20261006`)。段階 A は `-gn` 付きの arm (T = 2, 4, 8, 3) でやり直す (MIG3 で約 9 時間)
- 記録として: PC-ALM の重み (固定 epsilon) でも FT の勾配の向きは BP と cosine 0.88〜0.98 (T = 8〜2)、L1 は 0.31〜0.39 だった

## int8 への書き出しで PC-ALM のネットが壊れる (2026-10-07 未明) → 出力側を縮めた書き出し

- 旧方式の `s-pcalm-T2` の調整対局 (BP の複製相手, 300 ペア) は **600 局すべて詰みで負け (−3600 Elo)**。
  一方 float の一致率 (奏乗 10 万局面) は 75.3% で BP (76.3%) に近い。量子化した nn.bin の一致率は 53.9%
- `loss_eval --dequant` で量子化の誤差を分けると、**誤差はすべて重みの丸め・切り詰め**から来ていた (活性の丸めではない)
- 原因: PC-ALM で学習すると **L3 の実効重み (stack の重み + shared factorizer, それぞれ ±1.98 で clip) が int8 の範囲
  (|w| ≤ 127/64) を超える**。範囲外の割合は旧 T=2 で 82%、gn の T=2 で 80% (BP は 0%)。BulletOu の書き出しが切り詰める
- 仕組み (測定): BP の e1 の重みで、PC-ALM の L3 の重み勾配と L3 の重みの cosine は **T = 2, 4, 8 で −0.28, −0.43, −0.54**
  (BP は −0.016, T = 32 で −0.08)。PC-ALM の重みの更新は、落ち着いた (順伝播からずれた) 活性を使うので、L3 の重みを外向きに
  押す成分を持つ (負の weight decay のように働く)。Adam (Ranger) は大きさを正規化するので、この偏りが毎ステップ同じ大きさで
  積み重なり、重みが clip の上限に張り付く。T を大きくして平衡に近づくほど偏りは小さくなる
- 対処 (学習は変えない): **出力側の経路 (L3 の重みと bias、L1 の shortcut 行 = 7 行目とその bias) を 1/k にした nn.bin を書く**
  (`export_rescaled.py`, k は「範囲に収まる最小の 2 のべき」, PC-ALM では k = 2)。ネットの関数は出力が 1/k 倍になるだけなので、
  FV_SCALE を 1/k 倍にすれば探索での評価値は同じ。BP のネットは k = 1 (元の nn.bin とバイト単位で一致することを確認)
- 効果 (一致率, 奏乗 10 万局面): 旧 T=2 は 53.9% → 74.8% (float 75.3%)、gn の T=2 は 74.7% → **76.1%** (float 76.0%, BP 76.3%)
- 調整対局は書き出し直したネットを FV_SCALE 24 (= 元の 48 相当) で行う。`rescale_watch.py` が PC-ALM の checkpoint を自動で書き出す。
  gn の T=2 の「書き出しのまま」の対局も参考に残す (書き出しの切り詰めが何 Elo に当たるか)
- 本番規模 (M4) の FV_SCALE の格子も、PC-ALM のネットは k 倍した値 (32〜64 → 16〜32) で探す
- gn の T=2 の e1 では自動 η = 0.00016 (λ_max 約 6,000): gn でも重みの増大は止まらない (L1 の W1 も増える)

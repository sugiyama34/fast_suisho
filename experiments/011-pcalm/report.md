# experiment-011: PC-ALM は backprop より強い評価関数を学習できるか

作成: 2026-10-10 / ブランチ `exp/011-pcalm` (PR #28) / サーバー kajiki (GPU 0 の MIG device 2 / 3)
設計は [hypothesis.md](hypothesis.md)、作業ノートは [notes/](notes/README.md) (実装と検証は [notes/m0.md](notes/m0.md)、
決定の記録は [notes/decisions.md](notes/decisions.md)、全対局は [notes/ratings.md](notes/ratings.md))。

## TL;DR

- 問い: PC-ALM (Augmented Lagrangian Predictive Coding, Sakana AI, 2026) で学習した `SFNN_halfka2_1024-7-64-k3k3` は、
  backprop (BP) で学習したものより強いか。各手法とも最良の設定 (FV_SCALE を含む) で、同じ教師データ・同じ学習局面数の予算 (E ≤ 20) で比べる
- 答え: **PC-ALM の方が弱い** (事前に固定した判定規則, §4.5)。PC-ALM の最良 (e12) と BP の最良 (e16) の
  **直接対局は D = −80.5 Elo [−91.5, −69.7]** (2,000 ペア)。水匠 11 相手でも PC-ALM −177.6、BP −85.9 で、差は −91.7 [−108.0, −75.3]
- 調整 (小規模, 各手法 8 本前後) でも、PC-ALM のどの設定も BP の複製に対して −59 〜 −108 Elo で、BP の調整の幅 (−49 〜 +25) の外だった。
  本番規模では e5 から e20 まで、どの epoch でも PC-ALM の最良は BP の最良より 60〜95 Elo 低い
- 原因の候補 (測定): 有限の推論回数 T では PC-ALM の重み勾配が BP からずれ、特に出力層では重みを外向きに押す成分を持つ
  (学習済みの重みで重みとの cosine −0.43, T = 4)。学習中に重みが clip の上限に張り付き (L3 の 93%、L1 の 64% が int8 の範囲外)、
  e12 以降は強くならなかった
- 学習の実時間は PC-ALM (T = 4) が BP の 1.19 倍 (1 sb = 4,000 万局面あたり 74 s vs 62 s)
- 副産物: BP の学習率を調整し直したレシピ (LR ×0.7, lr-min ×3) は experiment-009 の BP より **+33.5 Elo [+17.8, +49.1]** 強い
  (水匠 11 相手 −85.9 vs −119.4, 同じ開始局面)
- 未集計: 本番規模の BP の複製 (ノイズ床 `N`) と、参照の PC (α = 0, T = 16) の本番規模。どちらも結論は変えない見込み
  (判定を覆すには `N` ≥ 80.5 が必要)。集計後に追記する

## 用語

- **PC-ALM**: ネットの各層の出力を独立変数 (状態) にし、層の式を制約として拡張 Lagrangian を作る。ミニバッチごとに
  状態を T 回の局所的な更新 (primal) と T − 1 回の双対変数の更新 (dual, 刻み α) で落ち着かせてから、重みを 1 回更新する。
  平衡点 (KKT 点) では重み勾配が BP と一致する。α = 0 が通常の predictive coding (**PC**)
- **T**: 1 ミニバッチあたりの推論 (状態の更新) の回数。**ρ**: 制約の二次ペナルティの重み。**η**: 状態の更新の刻み (自動設定)
- **gn**: 勾配の大きさの正規化 (本実験で追加, §方法)。**出力側 1/2 の書き出し**: int8 の範囲に収めるための nn.bin の書き出し (§方法)
- **sb**: superbatch = 4,000 万局面。1 epoch = 108 sb = 43.2 億局面。E = 20 で 864 億局面

## 方法

### 実装

- BulletOu (`2a8e5ed` + sm_120) に `--credit pcalm` を追加した ([bulletou-pcalm.patch](bulletou-pcalm.patch), BulletOu の作業ブランチ `pcalm-011` `807604bd`)。
  BP の経路は変えていない (`--credit bp` は改造前と同じ結果)。状態は pairwise 後 (1,024)、L1 出力 (8)、L2 出力 (64) の 3 つ。
  FT の前活性は推論中に変わらないので、疎な FT は順伝播 1 回だけ
- 検証 ([notes/m0.md](notes/m0.md)): CUDA と float64 の Python 参照実装の勾配が一致 (T ≤ 4 で相対誤差 1.2e-4 以下)。
  KKT 点 (双対変数 = BP の随伴の符号反転) では重み勾配が BP と厳密に一致 (cosine 1.000000)
- 状態は順伝播の値からの差で持つ (float32 の桁落ちで L1 の誤差が 4〜7% になったため)。刻み η は推論の作用素の最大固有値の上界から
  バッチごとに自動で決める (論文の `η = 1/λ_max` と同じ考え方。発散しない)
- **勾配の大きさの正規化 (gn, 論文に無い追加)**: PC-ALM の重み勾配は BP の 1/100〜1/1,000 の大きさで、Ranger (Adam 系) の
  epsilon (1e-7) が支配して FT がほとんど学習しなかった。バッチごとに PC-ALM の全勾配を同じ倍率で縮放し、FT の非零の勾配の平均 |g| を
  BP の典型値 4.0e-7 に揃える (向きは変えない)。固定の epsilon の較正も試したが、学習が進むと成り立たなかった
- **出力側 1/2 の書き出し (論文に無い追加)**: PC-ALM で学習すると L3 の実効重みが int8 の範囲 (|w| ≤ 127/64) を超え、
  BulletOu の書き出しで切り詰められて対局で全敗した (300 ペア全敗)。L3 (重みと bias) と L1 の shortcut 行を 1/2 にした nn.bin を書き、
  FV_SCALE も 1/2 にする (探索で使う評価値は元と同じ, `export_rescaled.py`)。PC 系のネットは常にこれで対局した。
  量子化と float の出力の差は BP と同程度 (e20 で平均 68 cp vs BP 51 cp、相関 0.9993 vs 0.9989, `quant_check.py`)

### 学習

- 教師は奏乗 (`dlsuisho_unique_001〜030.psv`, sha256 は検証済み)。レシピは experiment-009 と同じ (B = 65,536, Ranger, step の LR schedule,
  sigmoid-MSE, held-out は Floodgate 30 万局面)。手法と学習率以外は全 run 共通
- **調整 (小規模)**: 教師 9 ファイル (001 011 021 006 016 026 003 013 023) を 1 epoch (43.2 億局面)。各 run の e1 を
  BP の複製 `s-bp-lr1-rot` (同じ 9 ファイルを順序だけ回転) の e1 と 300 ペア対局し、**Elo 最大 (誤差内でも) を選ぶ** (loss は使わない, ユーザー決定)
- **本番規模**: 教師 30 ファイルを E = 20 (864 億局面)。BP は調整の最良がレシピと違ったので、最良の設定で学習し直した (ユーザーの規則)

### 対局

- 条件は experiment-009 と同一: やねうら王 V9.60 + `finny.patch` (**009 と同じバイナリ** `423b6b1c…`)、1 手 30 万ノード固定、
  Threads 1、Hash 256 MB、互角局面集 ply24 からストライド抽出、1 ペア = 先後入替 2 局。Elo の 95% CI は pentanomial
- エンジンの同一性: 009 の `full-e16 @ 48` の棋譜 50 ペア (100 局) を kajiki で指し直し、**100 局すべて指し手列と結果が一致**
  (`replay_check.py`)。009 の −119.4 と同じ条件で比べられる
- 調整の対局は kajiki でビルドした同じソースのエンジン (`a5f519d2…`) を使った (同一性は確認していないので、009 との比較には使わない)
- **checkpoint と FV_SCALE の選択** (009 と同一の手順, 両手法に共通): e5 / e8 は FV_SCALE 32〜64 (刻み 8)、e12 は e8 の最良 f の ±8、
  e16 / e20 は f − 8〜f + 16。格子の端が最良なら外側に 1 点足す。各点 400 ペア (水匠 11 @ 32 相手)、Elo 最大を最良として 2,000 ペアで測り直す
  (`select_queue.py`)。PC 系は FV_SCALE を 1/2 にした格子 (16〜32, 刻み 4)
- **判定 (事前に固定, hypothesis.md §4.5)**: D = 直接対局 (PC-ALM の最良 vs BP の最良, 2,000 ペア) の Elo。N = ノイズの目安。
  D の CI が 0 を含まず |D| > N のとき強い / 弱いと判定する

## 解釈

1. **有限の T では BP の勾配に近づかない**: 平衡点では一致するはずだが、学習で重みが大きくなると推論の作用素の最大固有値が
   増え (初期値 3.4 → BP の e1 で 58 → PC-ALM 自身の e1 で 1,000〜6,000)、安定な刻み η が小さくなる。BP の e1 の重みでは
   T = 1,024 でも FT の勾配は BP と cosine 約 0.75 で振動が続き、収束しなかった (初期値では T = 32〜64 で一致した)。
   実用的な T (2〜8) では FT の勾配の向きは BP と cosine 0.82〜0.87、大きさは 1/100〜1/1,000 ([notes/m0.md](notes/m0.md))
2. **出力層の重みを外向きに押す偏り**: BP の e1 の重みで、PC-ALM の L3 の重み勾配と L3 の重みの cosine は T = 2 / 4 / 8 で
   −0.28 / −0.43 / −0.54 (BP は −0.016)。負の weight decay のように働き、Adam 系は大きさを正規化するのでこの偏りが毎 step 同じ大きさで積み重なる。
   本番規模の e20 では L3 の実効重みの 93% と L1 (shortcut 以外の 7 行) の 64% が int8 の範囲 (|w| > 127/64) の外にあった
   (BP の e20 は L3 の 1.0%、L1 の 0.05%)。書き出しの関数の誤差は小さかったので
   (上の量子化の確認)、弱さは書き出しではなく、学習された重み自体にある
3. **双対変数 (α) は助けにならなかった**: 小規模では通常の PC (α = 0) の方が良く (T = 16 で −33.1)、α = 1.5 は悪化した。
   本番規模の PC の結果は集計中
4. 論文の主張は「BP に匹敵する」で、BP を上回る課題は報告されていない。本ネットのように FT が巨大で疎な入力・layer stack・
   出力が 1 つのネットでは、匹敵にも届かなかった

## 限界 (妥当性への脅威)

1. **調整の予算**: 各手法 8 本前後 (小規模, 1 epoch, 9 ファイル)、選択は 300 ペアの対局 (±27)。PC-ALM の最良の設定を取り逃している可能性はある。
   ただし調整で PC-ALM の設定を変えて動いた幅 (最良と最悪の差 49 Elo) より、本番規模の差 (80 Elo) の方が大きい
2. **論文に無い追加**: 勾配の大きさの正規化 (gn) と出力側 1/2 の書き出し。gn は向きを変えないが、Adam 系の epsilon との関係とバッチ間の重みを変える。
   gn なし (固定 epsilon) はさらに悪かった (−253.8)
3. **大きな T を試していない**: 本番規模の PC-ALM は T = 4。T を大きくすれば BP に近づくはずだが、学習済みの重みでは T = 1,024 でも近づかず、
   実時間も T に比例して増える (小規模の PC T = 32 は −47.2 で T = 16 より悪かった)
4. **本番規模は各手法 1 本**: BP の複製の 2,000 ペアは集計中 (`N` の確定)。小規模の複製の差は −11.0
5. **選択の上振れ**: 約 20 点 × 400 ペアから最良を選んだので、選んだ点の 400 ペアの値は上振れする (BP −75.0 → 2,000 ペアで −85.9、
   PC-ALM −159.8 → −177.6)。2,000 ペアの値は 400 ペアを含むので、わずかに上振れが残る。両手法に同じ手順を当てている
6. **BP の比較対象**: 「BP の最良」は kajiki で調整し直したレシピで、experiment-009 の BP より強い (+33.5)。PC-ALM は 009 の BP と比べても −58.1

